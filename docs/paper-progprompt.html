ProgPrompt: Generating Situated Robot Task Plans using Large Language Models

首发 2022-09-22精读版本 v1阅读原文 ↗
先记住这组证据

VirtualHome：完整 Codex 配置任务成功率 40%，动作可执行率 90%；这两个数字衡量不同事情。

看方法看实验看消融与边界做研究练习

01这篇要解决什么？

通用模型会说“打开冰箱拿食物”，但当前场景可能没有冰箱。ProgPrompt 将场景对象、可用动作、示例计划组织成类 Python 的提示，让模型补全一个具体环境中的程序。它还用注释提示子目标，用断言表达动作前必须满足的条件。

02方法怎样运转？

  1. 01

    描述这个世界有什么

    在提示中导入合法动作、列出对象。机器人能力与场景事实由外部系统提供。

  2. 02

    以程序示范任务

    示例使用函数、按步骤的注释和动作调用；注释帮助维持局部意图，减少计划漂移。

  3. 03

    用断言触发恢复

    例如抓取前检查是否靠近对象；条件不成立时先执行接近动作。断言只能覆盖模型实际生成且系统可检查的条件。

方法与结果的原文定位见本页引用。

03跟着一个例子想一遍

教学推演

教学推演：“把杯子放进柜子。”一个合法程序仍可能遗漏开门。显式写出“柜门已打开”的前置条件，就能在放入前插入 open；如果没有这项条件，代码可以调用合法动作，却无法达成目标。这正好解释为什么可执行率高于任务成功率。

04实验到底表现怎样？

主要量化实验在 VirtualHome，报告完整任务成功 SR、动作可执行 Exec 和目标条件满足 GCR。表 I 含提示组成消融，固定示例数随模型上下文限制略有不同。

怎样读这组数字

完整程序提示提高了多个指标，但 90% Exec 与 40% SR 的距离很大：动作逐步合法不保证最终完成任务。原文任务表里还出现 Exec 为 1、SR 为 0 的情况，适合训练自己区分“代码能跑”与“任务做对”。

05收益来自哪里，又停在哪里？

消融与机制证据

同一 GPT3 下，完整配置 SR 为 34%，去掉反馈是 28%，去掉注释是 30%，两者都去掉是 18%。这比跨 Codex / GPT3 比较更能隔离提示结构的影响。

结论的适用边界

真实机器人部分主要是少量定性展示，没有启用反馈断言，因为系统不能可靠跟踪状态；不能把仿真的完整反馈机制与真实结果混为一谈。

07把阅读变成一个小研究

讲义提出的研究练习 · 不是论文复现结果

写一个很小的柜子状态机，分开计数“动作是否合法”和“杯子是否最终入柜”；比较有 / 无前置条件检查的程序。

先自己回答：这项实验怎样才有解释力？

一个有力反例是：程序每条动作都合法，但遗漏放入杯子或最后又将杯子取出。只报告合法动作比例，会掩盖目标层失败。

合上原文后，试着回答
  1. 用自己的话说出这篇改变了哪个模块。
  2. 画出它的输入、输出和一次失败如何被处理。
  3. 复述一个结果，同时说清基线、指标与实验条件。
