先记住这组证据

LIBERO-Pro 消融：基础系统约 14%，执行证据引擎 62%，再加进化搜索 72%；长程迁移为 30.5%。

看方法看实验看消融与边界做研究练习

01这篇要解决什么？

机器人程序报错时，“任务失败”通常不够用。到底没看见目标、导航点不可达，还是夹爪抓偏？ASPIRE 为 coding agent 提供逐原语的多模态执行记录，让它检查因果链、修改程序，再将经过验证的修复方式存入技能库。

02方法怎样运转？

  1. 01

    逐调用暴露执行证据

    记录 API、输入输出、返回状态以及调用前后的图像、位姿、规划结果等；代理可以针对失败环节检查证据。

  2. 02

    提出并验证修复

    改程序后在调试配置上执行。进化搜索保留较好的候选及残余失败，探索不同方案，缓解单一路径反复打补丁。

  3. 03

    提炼可复用技能

    技能包含失败特征、适用条件、修复策略和必要代码片段；协调者审查后入库，再在留出配置或新任务中复用。

方法与结果的原文定位见本页引用。

03跟着一个例子想一遍

原文案例解读

原文 §2.1 案例：机器人已检测到收音机，却反复导航失败。日志显示接近目标落在桌边碰撞缓冲范围内；修复是从多个方向采样可行接近位姿。记住的应是“边界附近规划失败时尝试替代接近方向”，而不是只保存“这次收音机在哪个坐标”。

04实验到底表现怎样？

LIBERO-Pro 报告位置与指令扰动，并采用留出的 50 个评测 seed；另在 LIBERO-90 积累技能后，对 LIBERO-Pro Long 做不再调试的迁移。真实实验比较有 / 无技能，并同时报告成功率和 token。

怎样读这组数字

执行证据引擎带来的跳升最大，说明“能看清哪里坏了”是关键条件；进化搜索再解决一部分残余难题。长程迁移 30.5% 是另一种更难的协议，不能用 72% 代替。

05收益来自哪里，又停在哪里？

消融与机制证据

§3.7 区分引擎与进化搜索；附录表 5 还显示技能来源从 0、25、50 到 90 项任务时，长程总体为 4.7%、13.7%、21.5%、30.5%。积累的覆盖重要，但需计入训练任务上的调试成本。

结论的适用边界

技能可以是自然语言修复知识，不一定是独立可执行控制器。真实开 / 推抽屉使用技能后仍只有 11/20；自动复位、成功判断与长时间自主运行仍有工程限制。

07把阅读变成一个小研究

讲义提出的研究练习 · 不是论文复现结果

保留相同基础模型，比较只给“失败”、给最后一帧、给失败 API 前后证据三种修复方式；用新布局检验修复规则。

先自己回答：这项实验怎样才有解释力？

一条可迁移的教训应有适用条件和已验证证据。若只记某个 seed 的坐标，很可能是实例记忆；要通过留出布局才能证明更一般的技能。
