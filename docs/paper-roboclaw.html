01这篇要解决什么？

实体机器人学习的瓶颈常常不是缺少下一步计划，而是每做一次实验就要人来复位。RoboClaw 用同一 VLM Agent 连起采集、训练和部署，引入 Entangled Action Pairs（EAP）：正向任务改变场景，逆向策略把场景带回可再次练习的状态。

02先看一个场景

具体情境 · 先有画面，再看机制

取论文四项单技能里最难的“口红插入窄槽”。想练这条技能就得反复采数据，而每插进去一次，现场就变了：口红留在槽里，下一次演示无法开始。靠人把它取回来，采集速度就卡在人手上。

03方法怎样运转？

  1. 01

    三层抽象：Skills 调 Tools，Tools 调 Policies

    系统自上而下分成三层。最底层 Policies 是产生低层电机动作的机器人基础模型，这里由 VLA 模型 π₀.₅ 担任；中间层 Tools 是通过 Model Context Protocol（MCP）暴露的系统接口，包括 Start Policy、Terminate Policy、Change Policy、Env Summary、Fetch Robot Stats、Call Human；最上层 Skills 是编排这些工具的可复用流程，例如一个“长程执行”技能会先调 Env Summary 再调 Start Policy。做决策的是一个现成 VLM，以 in-context learning 的方式工作、不为机器人做微调，但论文没有给出它的具体型号与规模。

  2. 02

    记忆三件套驱动的 CoT 决策循环

    每个时间步 t，Agent 维护一个结构化记忆 m_t = (r_t, g_t, w_t)：r_t 是角色身份，规定当前是数据采集模式还是任务执行模式以及可用工具集；g_t 是任务级记忆，记录全局任务、拆出的子任务及各自的执行状态；w_t 是工作记忆，存当前激活的技能与工具调用历史。VLM 结合观测 o_t 与 m_t 做链式推理，顺序固定：先解读场景、再确定当前子任务与它的成功判据、再评估当前状态是否达标或需要纠正、最后决定下一个动作。结果写回记忆，形成感知—推理—动作的持续循环。

  3. 03

    EAP：每条正向策略配一条逆向复位策略

    对每项技能 k 都学两条策略，正向执行 π→_{θk} 与复位 π←_{φk}。正向执行采到轨迹 τ→ = {(o_t, q_t, a_t)}；只有当 Agent 判定子任务成功，才触发复位策略采出 τ←，把环境带回可以再练一次的前置区域，两段合成一个纠缠对 τ_k 一起进入数据集 D。逆向任务是被刻意设计得比正向任务简单的——它只需要可靠，不需要困难；表 2 里四项复位的成功率是 36/50 到 43/50，说明这条自复位环路本身也会断。还要注意条件策略用的语言指令 l_t 不是人给的，而是 Agent 在调用 MCP 工具时现生成的结构化子任务描述。

  4. 04

    底层策略怎么训：π₀.₅ 上的 LoRA 微调

    策略不是从零训练，而是在现成 π₀.₅ 上做 LoRA 微调：rank 16、alpha 16、dropout 0.1，目标模块为 all-linear，bfloat16 精度，batch 16，学习率 2.5×10⁻⁵，训练 1 万步，推理 3 步。训练目标是条件流匹配——学一个速度场 v_θ，把标准高斯噪声输运到真实动作分布，一次预测长度为 H 的动作块。训练数据有三个来源：人工示范、EAP 自主采集的轨迹、以及自主 rollout 失败后人介入纠错产生的数据；实验里每一轮迭代新增 50 条。

  5. 05

    部署：同一个循环，区分重试与恢复，必要时叫人

    部署时 Agent 用同一套闭环结构选下一个子任务，通过 MCP 启动对应的正向策略，并周期性调用 Env Summary 与 Fetch Robot Stats，把反馈写进工作记忆来判断子任务是否完成。达标就更新任务级记忆并进入下一个子任务；不达标则重试同一条策略，或用 Change Policy 换一条；若检测到反复失败或异常环境状态，就重新规划、从正向技能集里改选；自主恢复无效或触发安全条件时，通过 Call Human 上报。论文据此把失败分成两类：非降级失败（如抓空但瓶子仍直立，位姿基本没变）可以直接重试，降级失败（瓶子倒了或滑出前置区）必须先执行恢复动作。早期这类恢复靠人，随经验累积，恢复行为被逐步固化成专门的恢复策略进入策略库；部署期产生的轨迹同样回流进 D 用于继续改进策略。

04跟着这个场景走一遍

教学推演

教学推演：回到上面的场景。第一步，这条技能在系统里其实是一个 π₀.₅ 的 LoRA 检查点；Agent 看不到关节，它能看到的只是 Start Policy、Env Summary、Change Policy 这几个 MCP 工具。第二步，Agent 读到角色身份是数据采集者，任务级记忆里写着“练口红插入”，工作记忆还是空的；它先调 Env Summary 看一眼场景，确认口红此刻在起始区域，再决定启动正向策略。第三步是这篇的核心：正向策略把口红插进槽里，采到 τ→；Agent 判定成功之后才触发复位策略，把口红取回起始区，采到 τ←，两段合成一个纠缠对入库。之所以这条环路能自己转下去，是因为“从槽里取出来”本来就比“对准插进去”容易，复位被有意设计成弱任务。第四步，攒够一轮新轨迹后，在 π₀.₅ 上重做一次 LoRA 微调；表 3 显示口红插入从第 1 轮的 2/50 升到第 5 轮的 23/50——起点这么低，恰好说明早期环路主要是靠复位策略维持转动的，而不是靠正向策略成功。第五步，部署到“整理梳妆台”这条长程任务时，同一个 Agent 依次编排四条正向策略：某次抓空而口红还立着，它重试；口红被碰倒滚出前置区，重试就没有意义，必须先调恢复行为。这套机制没解决的是验证本身：成功与否仍由同一个 VLM 凭观测判定，系统里没有独立验证器，判错会让一条失败轨迹被当作正样本写进 D，污染下一轮微调。论文也把“存在实用的逆向复位行为”明确列为前提假设；顺着这个假设推下去（这是讲义的推论，不是论文的论断），倒水、切割这类结果不可还原的任务就配不出复位策略，整个数据引擎在那里转不起来。

06收益来自哪里，又停在哪里？

消融与机制证据

迭代轮数对照说明新增轨迹有助于单技能学习。长程实验还比较直接 π₀.₅ 和各子技能成功率的乘积估计；乘积是理论参考，不能当成实际跑过的闭环控制器。

结论的适用边界

模型来源是混合的：高层决策接的是一个现成 VLM，论文只写“off-the-shelf”，没有给出型号与规模，也不为机器人做微调，因此这一侧是可替换的（结论里还提到云端大模型会带来延迟）；而四条正向策略与四条复位策略全部由作者在 π₀.₅ 上用 LoRA 微调得到，加上每条正向策略固定的人工示范预算和失败后的人工纠错，这些才是系统真正的前提成本。还有两处结构性假设要记住：一是论文在结论里明确把“存在实用的逆向复位行为”列为限制，没有可靠复位就没有自采集环路；二是子任务成功与否由同一个 VLM 凭观测判定，系统内没有独立验证器，判错会把失败轨迹写成正样本。难任务如口红插入经五轮后仍只有 46%，因此自采集闭环并不保证很快学会所有技能。

08把阅读变成一个小研究

讲义提出的研究练习 · 不是论文复现结果

在仿真中设计正向和逆向任务，分别记录正向成功、复位成功、单位人工分钟有效轨迹数，再测试复位误差的累积。

先自己回答：这项实验怎样才有解释力？

如果只计采集总条数，会把无效或高度重复轨迹也算作成果。更合适的是同时检查独立测试性能和总采集成本。

先自己答，再看前两问的参考答案

这篇改了哪个模块这篇改的不是机器人怎么做事，而是训练数据怎么源源不断地来：每项技能被要求配一条逆向复位策略，正向执行改变了场景之后由复位把场景带回可以再练一次的前置区域，两段合成纠缠对一起入库，采集、训练与部署被同一个 Agent 和同一套 MCP 工具接口串成一个环，Agent 只在角色身份上切换。它没有改动作空间，也没有换控制器：策略仍是在现成 π₀.₅ 上做 LoRA 微调，高层决策接的是一个现成 VLM、不为机器人微调。被重新设计的是环路本身，以及谁负责把现场恢复到可以再采一条数据的状态；逆向任务还被刻意设计得比正向任务简单，因为它只需要可靠，不需要困难。

输入、输出与一次失败如何被处理Agent 看到的输入是观测 o_t 与结构化记忆 m_t = (r_t, g_t, w_t)：角色身份规定当前是数据采集模式还是任务执行模式以及可用工具集，任务级记忆记全局任务、拆出的子任务及各自执行状态，工作记忆记当前激活的技能与工具调用历史；关节层面的东西它看不到，环境摘要与机器人状态由 MCP 工具回报，条件策略用的语言指令也不是人给的，是 Agent 调工具时现生成的结构化子任务描述。输出是一次工具调用，落地形式是一次策略启停，低层动作由 π₀.₅ 的 LoRA 检查点产出；采集侧真正的产物是纠缠对，正向轨迹与复位轨迹成对写进数据集 D，每轮攒够新轨迹就重做一次 LoRA 微调。一次失败先由同一个 VLM 凭观测判定，再分两类处理：非降级失败（抓空但瓶子仍直立、位姿基本没变）直接重试同一条策略，降级失败（瓶子倒了或滑出前置区）必须先跑恢复动作，或用 Change Policy 换一条，自主恢复无效与触发安全条件时 Call Human 上报。系统里没有独立验证器，子任务成功与否就是那个 VLM 说了算，判错会把一条失败轨迹当正样本写进 D、污染下一轮微调；此外复位策略本身也会失败，采集环路会断在这里。

一次正向操作配一个逆向复位，机器人才能更连续地为自己采集训练数据。
