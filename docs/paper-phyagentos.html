PhyAgentOS: A Self-Evolving Operating System for Embodied Agents with Decoupled Cognitive Planning and Physical Execution

首发 2026-07-18精读版本 v1阅读原文 ↗
先记住这组证据

RoboCasa365 target50：π₀.₅ 首次 17.6%，经过验证触发的恢复后 26.8%；应同时看到增加的尝试。

看方法看实验看消融与边界做研究练习

01这篇要解决什么？

当一个系统接入很多机器人和策略，“函数返回了”会被误当成“任务完成了”。PhyAgentOS 将认知规划与物理执行解耦，用 session 描述目标、前置条件、执行边界和验收标准，让不同后端沿同一条生命周期运行。

02方法怎样运转？

  1. 01

    把目标编译成 session

    规划层选择运行方式和目标设备，记录目标、依赖、前置条件与验收条件；协议文档保存任务与环境状态。

  2. 02

    由 Runtime 负责执行

    适配器连接策略和设备，高频控制留在执行层；session 结束返回状态、轨迹及证据，而不是自动宣告成功。

  3. 03

    验收、恢复、沉淀

    SessionVerifier 返回 success / failure / replan；恢复形成可追踪的新尝试。验证过的成功方法和失败修正进入长期经验。

方法与结果的原文定位见本页引用。

03跟着一个例子想一遍

教学推演

教学推演：夹爪到达位姿且关闭，控制器正常退出，但杯子还留在桌上。运行时报告“动作完成”，验证器根据前后观测拒绝“取杯成功”。新 session 可以调整接近方向后重试；第一次失败保留在记录中，不能被最终成功覆盖掉。

怎样读这组数字

RoboCasa target50 的 250 次评估中，π₀.₅ 从 44 个成功增加到 67 个，恢复了 23 个 episode。相比之下，高起点的 LIBERO 只提升 0.8 个百分点。不同难度与可恢复失败比例决定了额外机制的收益。

05收益来自哪里，又停在哪里？

消融与机制证据

First / Final 是观察恢复效果的对照，但同时改变了尝试过程，不能单独证明“语义记忆”或“OS 架构”的贡献。若要研究这两者，应补上等重试预算的无记忆 / 无语义验收对照。

结论的适用边界

接入多种设备证明接口覆盖面，不等于每种设备都经过同等强度的端到端测试。本文 target50 的划分也与 Harness VLA 的 RoboCasa365 三个 split 不同，不能直接横比两篇总体数值。

07把阅读变成一个小研究

讲义提出的研究练习 · 不是论文复现结果

给已有 Agent 工具增加契约、执行状态和验收状态三个字段。模拟“正常退出但目标未满足”，检查是否错误推进下游任务。

先自己回答：这项实验怎样才有解释力？

记录首次成功、最终成功、平均尝试次数、误验收率。最终成功高却误验收多，可能只是系统自己宣布成功；外部独立判据必不可少。

  3. 复述一个结果，同时说清基线、指标与实验条件。
