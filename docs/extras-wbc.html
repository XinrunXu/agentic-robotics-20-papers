人形全身操作的七篇精读：成功怎么判、自由度归谁、横向表能不能比。

这一页是什么

主线的评测几乎全在桌面操作：LIBERO 及其扰动变体、RoboCasa、少量真机桌面任务。换到人形全身任务之后，成功的定义、控制权的划分与可比性都要重新定义。这七篇各有独立精读。

这些精读同样逐条回原文核对，实验数字都是作者报告；但它们不计入主线篇数，时间线仍是主线那一批。点表格里的标题进入精读，页面顶端会标出它属于哪一条支线。另一条支线见补充阅读：触觉。

01换到全身之后，哪三件事必须重新定义

一是“成功”的定义。桌面任务里整任务成功率和任务进度已经差得不小，全身长程任务里这个缺口通常更大，而且中途失去平衡这类失败没有对应的桌面概念——这七篇都只报整任务成功率或自定的进度分，没有一篇把摔倒单列为一类失败。

二是控制权的划分。哪些自由度由学习策略产生、哪些由传统全身控制器接管，决定了论文实际在比较什么。同一组里既有把下肢完全交给现成控制器、策略只出上半身与运动指令的做法，也有策略直接输出含双腿关节的全身动作、甚至把全部自由度收进一条策略的做法。读表之前先确认这一点，否则比的不是同一件事。

三是可比性。仿真 benchmark 与真机任务集往往不是同一套；有的横向表里各条基线的微调预算彼此不等，排名混进了适配成本。

A 组决定后面所有比较的地基，优先搞清楚任务怎么划分、成功判据写在哪里、每项跑几次；主线里 CaP-X 那套“分层 API 加显式调试预算”可以直接搬来审它们。B 与 C 组和 RoboHarness、EMERGE-Policy 是同一个问题换了身体，但交接处多了一层动力学可行性：这几篇的前置条件基本只保证几何可达，站得到不等于站得住，而 RoboHarness 是把交接目标取在支撑域与运动可达集的交集里。D 组回答的是“身体能做到什么”，在主线坐标系里相当于 RT-2 与 π₀.₅ 那一层：先认识被调用的执行器，再讨论怎样编排它。

03读这条线时问什么

  1. 哪些自由度是学出来的

    策略输出的是上半身关节加底盘速度，还是含双腿的全身指令？平衡由谁负责？这决定了两篇能不能并排比。

  2. 成功判据写在哪里

    几何阈值、人工细则打分，还是首次不可逆偏离前的归一化进度？摔倒与超时怎么计？这七篇的答案互不相同。

  3. 横向表里换了几个变量

    基线是否用同一套演示数据、同样的微调预算、同一条底层控制器？只要有一项不同，总体排名就不能当成方法优劣。
