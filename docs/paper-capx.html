CaP-X: A Framework for Benchmarking and Improving Coding Agents for Robot Manipulation

首发 2026-03-23精读版本 v2阅读原文 ↗
先记住这组证据

CaP-RL 的真实 Franka 抓取成功率：24% → 84%；但训练使用 S1 特权状态 API，不能混同所有评测层级。

看方法看实验看消融与边界做研究练习

01这篇要解决什么？

两个方法都声称“用代码控制机器人”，难度可能完全不同：一个调用 pick(object)，另一个必须从 RGB-D 定位物体、算位姿、控制夹爪。CaP-X 提供环境、分层基准、Agent0 和 RL 后训练方法，把这些条件拆开测。

02方法怎样运转？

  1. 01

    以接口分层控制难度

    S1–S4 区分状态真值 / 噪声感知、高层 / 低层原语及示例；M1–M4 加入多轮执行和不同形式视觉反馈。

  2. 02

    构造执行与调试循环

    CaP-Agent0 结合代码执行、视觉差分、技能积累与多路推理，利用环境反馈修复程序。视觉差分把前后视觉变化转成文本证据。

  3. 03

    用执行结果训练模型

    CaP-RL 在可验证奖励下用 GRPO 后训练代码模型；示范实验选择特权状态 API，以减轻感知噪声造成的归因困难。

方法与结果的原文定位见本页引用。

03跟着一个例子想一遍

教学推演

教学推演：同一句“叠两块积木”，高层 API 已封装抓取姿态和接触处理；低层 API 要求模型自己补齐这些步骤。若两种设置直接比较成功率，可能把工程封装当成推理能力。再允许一方调试十轮，比较就同时改变了接口与预算。

04实验到底表现怎样？

CaP-Gym 含更广任务集合；核心 CaP-Bench 用 7 项任务研究 12 个模型及不同接口条件。下表是论文 §5 的独立 CaP-RL 实验：Qwen2.5-Coder-7B 在 3 项任务训练，仿真每项 100 次、真实 Franka 每项 25 次。

怎样读这组数字

训练可以显著改善指定任务上的代码控制，但这张表不能证明基准中的每项任务、每种感知层级都得到同等提升。真实堆叠仍低于人工专家，仿真堆叠差距更大。

05收益来自哪里，又停在哪里？

消融与机制证据

§3.3 的分层实验发现，直接加入 RGB 的 M2 并未稳定优于文本反馈，视觉差分 M3 更有效。更多模态不自动等于更好；反馈必须能帮助定位代码与物理变化之间的关系。

结论的适用边界

人类参考程序经历调试，模型的单轮 Pass@1 是另一种开发成本。附录 K 中平均试验时长也随多轮机制增长；比较成功率时必须同时报预算。

07把阅读变成一个小研究

讲义提出的研究练习 · 不是论文复现结果

为自己的方法填写一张评测契约：输入、可用 API、reset 权限、训练 / 调试 seed、每任务调用预算、成功判据。

先自己回答：这项实验怎样才有解释力？

先保证对照在这些条件上可比，再讨论方法收益。否则实验可能测到“谁获得了更多信息或更多尝试”，而非你想研究的机制。

合上原文后，试着回答
  1. 用自己的话说出这篇改变了哪个模块。
  2. 画出它的输入、输出和一次失败如何被处理。
  3. 复述一个结果，同时说清基线、指标与实验条件。
